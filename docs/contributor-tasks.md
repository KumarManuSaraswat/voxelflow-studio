# Ways to help VoxelFlow

Start with one small, reproducible contribution. Check open issues and leave a comment before substantial implementation so work is not duplicated. Read [Contributing](../CONTRIBUTING.md) for setup and review expectations.

| Task | Good fit for | A useful finished contribution |
| --- | --- | --- |
| Try a fresh installation | Artists and testers | OS/app versions, where each setup step succeeded or failed, diagnostic output with private details removed |
| Improve a prompt example | Artists | Prompt, screenshot, editable source, license, and notes on manual changes; see the [prompt gallery](../plugins/voxelflow-studio/PROMPTS.md) |
| Clarify one setup step | Writers | A focused guide correction backed by an actual fresh installation |
| Test macOS or Linux | Platform testers | Node/Blockbench versions, startup/discovery/export results, and a reproducible failure report; these platforms are not yet verified |
| Verify a Bedrock export in game | Minecraft creators | Game version, the extra integration files used, content-log findings, and reproduction steps; do not infer gameplay support from a valid ZIP |
| Add in-place prop editing | Experienced developers | Discuss the design first: preserve part identity, painted textures, native approval, Undo, and stale-scene checks; include meaningful regression and editor tests |

## Report a useful result

Use [installation reports](https://github.com/KumarManuSaraswat/voxelflow-studio/issues/new?template=installation.yml) or [model showcases](https://github.com/KumarManuSaraswat/voxelflow-studio/issues/new?template=showcase.yml). Successful installation reports are valuable too. Please label what was actually tested, and do not include pairing files or connection tokens.

Maintainers review contributions as time permits. No contributor is expected to buy a subscription or donate to participate.
